# Frontend and UI Skills

Create a frontend-specific skill when visual behavior, design-system rules, state boundaries, or accessibility checks repeatedly need project context.

## Good candidates

| Repeated concern | Skill boundary | Evidence to collect |
|---|---|---|
| Shared visual primitives | UI conventions | Component library, tokens, layout patterns, component tests |
| Navigation and state | Feature delivery | Routes, loaders/actions, stores, query cache, error states |
| Accessible interaction | Accessibility review | Keyboard flows, semantics, focus behavior, target standards |
| Visual regression risk | UI verification | Story/test setup, screenshot process, viewport matrix |

## Authoring notes

- State whether a component is source-owned, generated, or supplied by a design system.
- Include loading, empty, error, disabled, keyboard, and narrow-viewport behavior when relevant.
- Link to real tokens and components rather than copying a large style guide.
- Avoid claiming pixel accuracy or browser coverage without a verified test process.

## Done definition

The skill should direct a contributor to the approved primitives, state model, user-visible edge cases, and evidence required for a safe UI change.
